# IdeaGit — App Shell and Read-Only Log (Design)

Date: 2026-11-08
Status: Approved design. Waiting for the user to review this document.
Parent spec: `2026-11-08-ideagit-rust-design.md`. This document refines its "Shared infrastructure" and "Git Log" sections for the first runnable build.

## Goal

The first runnable IdeaGit. You can open a folder, see IntelliJ's New UI look (theme, icons, fonts, tool-window stripes), browse the Git history in a read-only **Log** tab with IntelliJ's graph, and watch the **Git Console**. The app runs on macOS, Windows and Linux.

## Scope

In scope:
- **App windows:**
  - Welcome window with Open… and a recent projects list. Clone is shown disabled.
  - One project window per opened folder, with all git roots detected via `ig_git::roots::detect_roots`.
- **Window chrome:**
  - New UI tool-window stripes and docking, using `gpui-component`'s dock restyled as IntelliJ's.
  - A **Git** tool window with a **Log** tab and a **Console** tab.
  - A status bar showing each root's current branch and background progress.
- **Menus:**
  - Native menu on macOS; an in-window menu on Windows and Linux.
  - File: Open, Recent, Close Project, Quit.
  - View: Tool Windows, plus a "Show read commands in Console" debug toggle.
  - Git: Refresh Log.
  - Help: About.
- **Read-only Log tab:**
  - Columns: graph and subject with ref labels, author, date, short hash.
  - Virtualized rows, keyboard selection and multi-select.
  - Long-edge arrow hover and click (click jumps to the target row).
  - Refresh on demand, on window focus, and after commands IdeaGit runs.
- **Git Console tab:** IntelliJ's console format, showing non-silent commands, plus the debug toggle above.
- **Theme:** light and dark, following the OS appearance.

Out of scope, in later plans:
- details pane, changes tree, filters, context actions (Log UI plan)
- editor and diff
- commit tool window
- branches popup
- fetch, pull and push
- clone
- file watching
- settings UI beyond the git path field
- packaging and signing

## Key decisions

| Decision | Choice |
|---|---|
| UI stack | `gpui` 0.2.2 + `gpui-component` 0.9.0 (crates.io), versions pinned exactly. |
| IntelliJ look | Assets imported from the pinned upstream commit with `cargo xtask import-ui`: theme JSON, `expui` SVG icons, bundle strings, keymap XML. Metrics are hand-ported from `JBUI` sources. |
| Dock and table | `gpui-component`'s dock and table, restyled. A **spike** (the first task) checks they can match IntelliJ's look. If they can't, those two widgets become our own (fallback approach C) and the rest of the design is unchanged. |
| Graph cell | Our own GPUI element, drawn from `ig-log` print elements. It ports upstream `SimpleGraphCellPainter` and `LabelPainter`. |
| Log data | One background log worker per project window. It owns `GitLogProvider`, `InMemoryStorage` and `VcsLogRefresher`. It sends immutable snapshots to the UI and loads metadata lazily per visible range. |
| MSRV | If GPUI needs a newer Rust than 1.85, raise the workspace MSRV to match and record the reason. |

## Architecture

```
crates/
  ig-git, ig-log      (unchanged)
  ig-ui-kit/          theme (generated tokens), icons, fonts, metrics, IntelliJ-styled wrappers:
                      tool-window stripe/header, status bar, notifications, table styling,
                      graph colour palette (port of DefaultColorGenerator)
  ig-app/             main(), action registry + keymap (IntelliJ action ids), settings (settings.toml),
                      welcome window, project window, Git tool window (Log tab, Console tab),
                      log worker
xtask/                import-ui (assets + generated theme tokens), screenshots
assets/               generated by import-ui: themes, icons, strings, keymaps, fonts
```

Dependency direction: `ig-app` → `ig-ui-kit`, `ig-git`, `ig-log`. `ig-ui-kit` has no Git knowledge.

## UI fidelity

**Theme.**
- `expUI_light.theme.json` and `expUI_dark.theme.json` are imported with their parent-theme chain resolved.
- The editor colour schemes supply VCS, Log and console colours.
- The import generates a typed `Theme { light, dark }` containing only the keys IdeaGit uses. Generation fails if a key is missing.

**Icons.** The `expui` SVGs listed in `assets/icons.list`, with dark variants where they exist.

**Strings.** The keys used from `VcsLogBundle`, `GitBundle` and `VcsBundle`. English only for now.

**Fonts.**
- Inter and JetBrains Mono (both OFL), embedded in the binary.
- Source: upstream's bundled fonts if they are present at the pinned commit. Otherwise the official releases, with their licenses recorded in `NOTICE`.

**Metrics.** Hand-copied constants: Log row height, stripe width, tool-window header height and similar. Each one cites its upstream `JBUI.CurrentTheme` source.

**Graph colours.** `ig-log` branch colour ids are mapped onto upstream's palette, following `DefaultColorGenerator`.

**Visual reference.** `docs/ui-reference/` holds screenshots of IntelliJ IDEA Community's Git Log, taken with the same fixture repo in both themes. They are compared by eye; there is no pixel diff.

## Read-only Log tab

**Graph and Subject column.**
- The graph is painted from `RowInfo::print_elements()` with lane width, node radius, line thickness and arrows taken from `SimpleGraphCellPainter`.
- Ref labels are drawn to the right, sorted with `VcsLogRefManager::sort_labels`. When space is short they are grouped and compacted as upstream's `LabelPainter` does.

**Author, Date, Hash columns.**
- Date uses IntelliJ's relative format: today and yesterday as words, otherwise a date.
- Hash is shown with 8 characters.

**Interaction.**
- The table is virtualized, with keyboard selection and multi-select.
- Arrow hover and click go through `ActionController`. A jump selects and scrolls to the target row.
- Print elements are snapshots: re-fetch them after any answer with `is_repaint_required`.

**Data flow.**
1. The project window starts one log worker: a dedicated thread with a command channel.
2. The worker calls `initialize()`. The data-pack handler only forwards packs over a channel and never re-enters the refresher.
3. For each pack the worker:
   - builds the visible graph (`Options::default()`)
   - computes `recommended_width()`
   - loads metadata for the first visible rows
   - sends an immutable `LogSnapshot` to the UI
4. **Metadata cache.** Upstream's `MiniDetailsGetter`/`TopCommitsCache` idea:
   - It is filled from the refresher's recent-details consumer, then from `read_metadata` in batches of 100 for the visible range.
   - Rows not yet loaded show "Loading…".
5. **Refresh.**
   - Triggers: the `Vcs.Log.Refresh` action (shortcut from the imported keymap), window focus, or a command IdeaGit itself ran.
   - The worker coalesces requests, then runs `repository_manager.update()` and `refresh(roots)`.

## Git Console tab

- A console sink forwards `ConsoleEvent`s to a UI entity.
- Each entry renders the timestamp, the command line in the console "command" colour, and the output lines.
- Non-silent commands only, as in upstream. The debug toggle also shows read commands, which is an IdeaGit addition.

## Errors

- **Git missing or too old.** Detected at startup with `Git::detect`. A banner in the welcome window, as in IntelliJ, plus a git path field that is saved to settings.
- **Log load errors.** Error data packs appear as an error state in the Log tab, with a Refresh link and the `VcsException::message` text.
- **Worker panics.** Caught at the thread boundary, logged to `ideagit.log` in the OS log directory, and shown as an error notification. The worker restarts on the next refresh.
- **No repositories in the opened folder.** A "No Git repositories found" state in the Log tab.

## Testing

- **Logic, without GPUI:**
  - the log worker and snapshot building
  - the metadata cache
  - the relative date formatter
  - palette mapping
  - console formatting
  - persistence of the recent projects list
  - `import-ui` against a fixture tree, including the missing-key failure
- **UI logic, with the GPUI test context (if its 0.2 test support allows; the spike confirms):**
  - the dock toggles
  - the Log scrolls and selects
  - an arrow click jumps
  - Refresh triggers the worker
- **Screenshots.** `cargo xtask screenshots` renders a fixture repo's Log in light and dark for side-by-side review. It is run by hand.
- **Manual checklist** (`docs/app-shell-checklist.md`):
  - open a real repo
  - scroll a 50k-commit history (the Plan 2c perf fixture)
  - refresh after a commit
  - switch the OS theme
  - open a multi-repo folder
  - git missing

## CI

- The existing jobs stay: fmt, clippy, doc and test on three OSes, plus the MSRV job.
- The Linux job installs GPUI's system libraries: xkbcommon, wayland, x11 and vulkan headers.
- Tests that need a GPU or a display are excluded or `#[ignore]`d on CI if the spike shows they can't run headless.

## Run

`cargo run -p ig-app -- [path]` opens a folder directly. With no path, it shows the welcome window.
